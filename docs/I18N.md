# Idiomas (i18n)

O app fala português (Brasil), inglês e espanhol. O português é a fonte; os outros dois
seguem as mesmas chaves, e a checagem de tipos (`npm run typecheck`) falha se faltar ou
sobrar uma chave em qualquer idioma.

## Onde fica

- `app/src/renderer/lib/i18n.svelte.ts`: o idioma em uso, o `m` (os textos), o `fmt`
  (datas, números, listas, ordem alfabética) e o `around` (texto com destaque no meio).
- `app/src/renderer/lib/i18n/<pt|en|es>/<área>.ts`: os catálogos, um arquivo por área
  (`common`, `app`, `chat`, `home`, `guild`, `server`, `settings`, `kit`, `lib`, `map`,
  `errors`). Os de `en` e `es` terminam com `satisfies typeof pt`.
- `app/src/main/i18n.ts`: os textos do processo principal (bandeja, avisos, atualização).
  O idioma chega pela interface (`window.resenha.setLocale`, IPC `locale`) e fica no
  `desktop.json` pra bandeja abrir certa.
- Escolha do idioma: Configurações → Aplicativo → Idioma (`settings.language`: `auto`,
  `pt`, `en` ou `es`). O automático segue o sistema (`navigator.languages`; fora dos três,
  inglês). Quem já usava o app antes da 1.9 fica em português (o `load` das configurações
  põe `pt` quando já existia configuração salva sem idioma).

## Como escrever

```svelte
<script lang="ts">
  import { m, fmt } from '../../lib/i18n.svelte'
  const t = $derived(m.chat.composer)        // atalho pra área, sempre com $derived
</script>

<button aria-label={t.send}>{t.send}</button>
<p>{t.typing(name)}</p>                       <!-- texto com valor: função no catálogo -->
<time>{fmt.date(ms, { day: 'numeric', month: 'short' })}</time>
```

```ts
// Catálogo (pt/chat.ts). en/chat.ts e es/chat.ts têm as mesmas chaves.
export default {
  composer: {
    send: 'Enviar',
    typing: (name: string) => `${name} está digitando…`,
    members: (n: number) => (n === 1 ? '1 membro' : `${n} membros`),
  },
}
```

Regras:

1. **Leia o texto na hora de mostrar.** No template, num `$derived`, ou dentro da função
   chamada no clique. Nunca numa constante comum (`const label = m.x.y`) nem no topo de um
   módulo: aquilo é lido uma vez só e não troca quando a pessoa muda o idioma. Tabelas de
   rótulos (`{ dnd: 'Não perturbe', ... }`) viram objetos no catálogo
   (`m.common.presence[status]`) ou funções.
2. **Texto com valor ou plural é função no catálogo**, e cada idioma monta a frase do seu
   jeito (ordem das palavras, plural, gênero). Nada de juntar pedaços com `+` no componente.
3. **Destaque no meio da frase** (negrito, link): a frase inteira no catálogo com um
   marcador, e `around(texto, '{nome}')` devolve `[antes, depois]`.
4. **Datas, números e ordem alfabética pelo `fmt`** (`fmt.date`, `fmt.number`,
   `fmt.relative`, `fmt.list`, `fmt.region`, `fmt.compare`). Nada de `'pt-BR'` fixo.
5. **O português continua igual, letra por letra**: os testes (e2e) procuram os textos
   em português.
6. Não se traduz: dados das pessoas (nomes, mensagens, canais), ids, `data-setting`,
   nomes de teclas, logs do console, comentários (seguem em português) e os protótipos
   (`ui/proto`, dados de exemplo).
7. Tom: o mesmo do português, curto e informal. Inglês natural de app (estilo Discord).
   Espanhol neutro da América Latina, com "tú". "Resenha" é o nome do app, não se traduz;
   "call" vira "call" em inglês e "llamada" em espanhol.

## Erros do servidor

O servidor responde em português. O app traduz pelo texto exato (`m.errors.server`, chave =
mensagem do servidor) na hora de mostrar: em `lib/api.ts` (HTTP) e no `case 'error'` dos
WebSockets. Mensagem que não está no catálogo aparece como veio. O teste
`app/test/server-errors.test.mts` confere que toda mensagem do `server/src` está lá: erro
novo no servidor precisa da tradução, e mensagem que sai do servidor tem que sair do
catálogo também. O nome do aparelho na lista de sessões ("App no Linux") também é gravado
em português e traduzido na hora de mostrar (`DevicesPage`).

## Como conferir

- `npm run typecheck`: chave faltando ou sobrando em qualquer idioma.
- `npm -w app run test:ui`: a busca das configurações nos três idiomas e os erros do servidor.
- `npm -w app run e2e`: abre em português (`LANGUAGE=pt_BR`), troca pra inglês e espanhol,
  passa pelas configurações, pelas do servidor e pelo início, e falha se sobrar português na
  tela (o que as pessoas escreveram não conta). Com `RESENHA_SHOTS` salva cada tela.
- Capturas dos protótipos noutro idioma: `PROTO_LANG=en npm -w app run proto:shots`.
- O que vem do servidor como dado continua em português: as categorias "Canais de texto" e
  "Canais de voz" de servidor novo, e o nome dos canais.
